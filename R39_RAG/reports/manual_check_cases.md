身份按检测框逐帧跟着走，IoU 低于 0.7 算这一帧没对上。单帧没有全局 ID、下一帧又回到同一 ID，记成导出空洞，不记成切换。数字来自各实验自己的 `result.json`，没有事后把 ID 对齐。

## 建议接着看的片段

1. 南向 98–110 帧，Aw 框 `[575, 203, 638, 254]`。原版在 102 帧换 ID，修复版保持 ID 2。
2. 北向 113–120 帧，Ce 框 `[229, 202, 317, 254]`。原版在 117 帧换 ID，修复版保持 ID 18。116 帧旁边 IoU 0.51 的框不应被算成这辆车。
3. Ce 画面右边缘，`x0 > 1800`。A+ 上这些框落在短轨迹 190、94、157、96，或 30 次没有全局 ID。请看它们有没有被吸进画面中间的长轨迹。
4. Aw 远端小框，约 `[681, 96, 710, 116]`，置信度约 0.77，投影约 `(21.5, -208)`。A+ 上 ID 1 用到 699 帧，700–703 帧没有全局 ID，704 帧起变为 225。原版同样在 700–703 帧丢失 ID，704 帧起变为 59。道路范围外，知识按设计不加分。
5. Bn 画面上方约 y=98 的两个重叠小框，投影约 x=-318。其中一个在 A+ 上 ID 17 从 89 帧维持到 141 帧，旁边另一个框在 89、93、101、108、141 帧连续换 ID。请确认是重复检测，还是同一辆车被拆开。
