# STMC 身份切换根因

诊断对象是留出序列 `r39_20251021_070327` 前 240 帧的原始 STMC，知识开关关闭。检测和 ReID 与上一轮对照实验相同。帧号下面同时给出结果 JSON 的 `frame_index` 和 STMC 内部帧（内部帧 = `frame_index + 1`）。

数值来自两处，都可以复现：

- 用各相机标定把检测框底边中心做 Homography 投影，并按 `SuperTrack.update / predict / reset` 重放每个相机槽位
- `STMC_DIAG=1` 跑到内部帧 118，边权写在 `outputs/r39_holdout_diag/edges.jsonl`

## 案例一 南向 20.3 m 已确认

`R39_Aw_CamS` 银色车，结果帧 101 全局 ID 2，结果帧 102 换成 ID 49。两个框底边中心的直接投影是：

| 结果帧 | 框 | 仅 Aw 投影 | 导出的 BEV |
| --- | --- | --- | --- |
| 101 | `[574.8, 203.3, 637.5, 255.1]` 置信度 0.953 | `(-15.29, -64.60)` | `(-19.09, -45.00)` |
| 102 | `[575.1, 202.7, 637.8, 254.2]` 置信度 0.952 | `(-15.20, -64.93)` | `(-15.20, -64.93)` |

仅 Aw 的相邻位移是 **0.346 m**。导出位置相差 **20.305 m**。

进入内部帧 103 时，旧轨迹 ID 2 的四个相机槽位是：

| 相机 | BEV | track_where | inactive_since | 最后真实观测 |
| --- | --- | --- | --- | --- |
| Aw | `(-15.25, -64.77)` | True | 0 | 内部帧 102 |
| Bn | `(-19.78, -37.47)` | False | 2 | 内部帧 32 |
| Ce | `(-19.54, -34.75)` | False | 2 | 内部帧 16 |
| Ds | `(-21.73, -43.18)` | False | 2 | 内部帧 47 |

四槽平均是 `(-19.08, -45.04)`，与结果帧 101 的导出值一致。`reset()` 只把 `track_where` 设为 False，**不清除** `positions_3d`。`mean_positions_3d` 和逐相机距离的 `nanmean` 都会继续使用这些冻结坐标。

新检测只有 Aw 投影 `(-15.20, -64.93)`。逐相机距离是 Aw 0.171 m、Bn 27.838 m、Ce 30.493 m、Ds 22.706 m，平均 **20.302 m**。这就是关联里的 20.3 m。

现场边权（内部帧 103，旧 ID 2，`same_group=false`）：

- 外观余弦 0.800，缩放后 `(0.800-0.7)/0.3 = 0.333`
- 空间项 `1 - 20.30/8 = -1.538`
- 合成 `0.5×0.333 + 0.5×(-1.538) = -0.602`
- 两帧图像框几乎重合，预匹配再加 `+0.60`
- 最终边权 **-0.003**

负边被 Multicut 切开。Aw 自己的预测只把位置从 `(-15.29,-64.60)` 挪到 `(-15.25,-64.77)`，不是 20 m 的来源。单应本身也不是来源。

**已确认：** 车辆离开共视后，失效相机的历史 BEV 仍进入平均，把 0.35 m 的同相机位移变成 20.3 m，再把预匹配几乎抵消成一条负边。

**不是原因：** 原始投影把两框投出 20 m；`patience` 在这一帧删掉了轨迹；JSON 重编号。轨迹状态仍是 ACTIVE，`lost_since=0`。

## 案例二 北向漏一帧 已确认是另一种机制

`R39_Ce_CamN`，结果帧 115 到 117。这条轨迹从头到尾只有 Ce 一个槽位，不存在多相机融合。

| 量 | 数值 |
| --- | --- |
| 结果帧 115 直接投影 | `(-43.13, 18.22)` 置信度 0.726 |
| 结果帧 116 | 该框不在检测里 |
| 结果帧 117 直接投影 | `(-42.74, 17.33)` 置信度 0.760 |
| 两帧直接投影距离 | 0.966 m |
| 进入内部帧 118 时的槽位距离 | 0.35 m |
| 外观余弦 | 0.947 |
| 边权 | **+0.889** |
| 状态 | ACTIVE，`lost_since=0`，`inactive_since=1`，`track_where=True`，最后真实帧是内部帧 116 |

`inactive_since > patience` 才摘掉相机，漏一帧不会进入 LOST，轨迹还在内存里。正确边存在，而且是强正边。Multicut 仍给出 `same_group=false`。

同一帧里，旁边另一辆车的检测 `(-39.82, 15.89)` 把旧 ID 18 吸进去了：

| 边 | 距离 | 外观 | 边权 | 同一组 |
| --- | --- | --- | --- | --- |
| 旧 ID 18 → 正确框 | 0.35 m | 0.947 | +0.889 | 否 |
| 旧 ID 18 → 旁边的框 | 3.53 m | 0.920 | +0.647 | 是 |
| 旧 ID 32 → 旁边的框 | 0.22 m | 0.971 | +1.537 | 是 |

ID 18 和 ID 32 因此进了同一组。正确框与旁边的框是同相机同帧，互斥边为 -100，正确框不能再加入这组，于是新开 ID。完整 1200 帧导出里，这条轨迹的全局 ID 在结果帧 117 从 18 变为 52。切换发生在 Multicut，导出阶段只做框对齐和重编号。

预匹配只看上一帧。结果帧 116 没有这辆车的框，正确轨迹的 `frame` 停在 116，接不到内部帧 118 的新框，所以正确边没有 `+0.60`。旁边那辆车帧帧都在，预匹配把它的边抬到 +1.537。

**已确认：** 漏检一帧后正确边很强，但 3.5 m 外、外观余弦 0.92 的另一辆车把旧轨迹吸进自己的组，同帧互斥再把正确框挡在外面。

**已排除：** 轨迹已被删除；正确边权不足；类别不一致；BEV 融合误差。

## 尚未当成事实的部分

没有逐条打印旧轨迹 ID 18 和 ID 32 之间的直接边。两者都与旁边那个检测同组，合并关系由这个共同组确定。ReID 为何给 3.5 m 外的车 0.92 的余弦，本次没有再拆特征，只确认这个余弦确实进了边权。

`tracker.position_state.active_cameras_only=true` 且 `tracker.short_recovery.enabled=true`，知识仍关闭。边权在 `outputs/r39_holdout_aplus_diag/edges.jsonl`。历史槽位没有删除，只是 `track_where=false` 的相机不再进入距离。

- 距离 **0.17 m**，外观 0.965，边权 2.131，`same_group=true`
- Aw 槽位 `(-15.3, -64.8)` 且 `track_where=true`
- Bn、Ce、Ds 仍保留旧坐标，但 `track_where=false`，没有再把平均拉到 20 m
