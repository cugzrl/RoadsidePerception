根因数值在 `R39_RAG/reports/stmc_root_cause_report.md`。本报告回答修复和知识对照之后的六个问题。

两段留出序列都是源视频 3600 帧、60 FPS，按 20 FPS 抽样 1200 帧，时长 60 秒。检测和 ReID 特征各序列只提一次，四个实验共用。知识库仍只用四段建库序列，没有用留出序列，也没有改原来的 sqlite 和 npz。

实验 A 的结果在 `variants/A`。流水线目录下那份 `result.json` 只跟踪到结果帧 117，不能当作原版全长结果。

## 六个问题

1. **20.3 m 从哪来。** 南向 Aw 两个相邻框的底边中心直接投影只差 0.35 m。旧轨迹在离开共视之后，Bn、Ce、Ds 的 `positions_3d` 仍保留很早的坐标，`track_where` 已经是 False，平均时却照样算进去。四个槽位的平均距离是 20.302 m。外观项加空间项得到 -0.602，预匹配 +0.60 之后边权只剩 -0.003，Multicut 把边切开。投影、预测和 JSON 重编号都不是这 20.3 m 的来源。

2. **115–117 为什么没接回原 ID。** 北向这辆车只有 Ce 一个槽位。漏一帧后轨迹仍是 ACTIVE，正确边权 +0.889，距离 0.35 m。旁边 3.53 m 的另一辆车边权 +0.647，并且和它自己的轨迹以 +1.537 连在一起。同帧同相机互斥是 -100，正确框进不了那一组，于是新开 ID。完整序列导出里是全局 ID 18 在结果帧 117 变为 52。预匹配只看上一帧，跨过漏检帧加不上。

3. **基础修复是否接上了这两例。** 接上了。A+ 在全长 1200 帧上，南向种子从结果帧 101 起保持全局 ID 2，102 帧和 108 帧都没有换 ID。北向种子从 115 帧起保持全局 ID 18，116 帧漏检没有把旁边 IoU 0.51 的车并进来，117 帧仍是 18。开关默认关闭，单元测试覆盖了失效相机不再拉大距离、默认路径仍使用全部槽位、漏检加分、以及连续帧不再叠一次短时加分。

4. **知识在修复后的 STMC 上还有没有独立收益。** 这两段留出序列上没有。K、D+ 与 A+ 的全局 ID 序列哈希一致：070327 都是 `1b6cae82f28f`，070428 都是 `69c5fe358193`。原版 A 分别是 `ceba09b2bee9` 和 `42f7c00ab366`。知识日志里负边被抬成正边的次数是 0。有界加分最大约 0.11，没有改变 Multicut 的划分。本次没有加大知识权重。

5. **原先的错误关联是否压住。** 知识不再把负边抬成正边。070327 的 K 有 4 条负边、D+ 有 0 条，加分后都没有越过 0。070428 的 K 和 D+ 各有 16 条负边，同样没有越过 0。Ce 右边缘的框在 A+ 上是短轨迹或没有 ID，没有并进一条很长的别的车。道路外和静止跳变按门控不加延续分。

6. **完整一分钟里远端是否还有明显换 ID。** 有。修复掉的是南向那辆共视失效的车，以及北向漏一帧的车。投影已经到道路外的小框还会断。070327 的 Aw 上，框约 `[681, 96, 710, 116]`、置信度约 0.77、投影约 `(21.5, -208)`，A+ 的 ID 1 维持到 699 帧，700–703 帧没有全局 ID，704 帧起变为 225。原版在同样四帧丢失 ID，704 帧起变为 59。同相机高 IoU 换 ID 次数只从 64 降到 54，其中高度小于 40 像素的仍有 18 次。
